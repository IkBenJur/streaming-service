This document describes the technology stack and patterns used in this project. Use it as a blueprint when starting a new frontend.

## Project Structure

```
app/
├── routes/                  # File-based routing (React Router framework mode)
│   ├── home.tsx             # / home page
│   ├── login.tsx            # /login
│   └── _auth/               # Auth-guarded layout group
│       ├── layout.tsx       # Guard loader + shared layout
│       └── *.tsx            # Protected pages
│
├── components/              # Reusable UI components, domain-organized
│   ├── <domain>/
│   └── ui/                  # shadcn/ui generated components
│
├── hooks/                   # Custom React hooks
│   ├── mutations/           # One file per mutation (useMutation)
│   └── queries/             # One file per query group (useQuery / queryOptions)
│
├── services/                # API call functions (no hooks, pure async)
│
├── types/                   # TypeScript types/interfaces, one file per domain
│
├── lib/
│   ├── apiClient.ts         # Singleton HTTP client wrapping fetch
│   ├── env.ts               # Zod-validated environment variables
│   ├── queryClient.ts       # Shared QueryClient instance
│   └── utils.ts             # cn() helper for merging Tailwind classes
│
├── root.tsx                 # Root layout (html shell, QueryClientProvider)
└── routes.ts                # Route manifest (auto-generated or hand-written)
```

React Router framework mode uses `app/` as the source root by convention. The `routes.ts` file declares which files map to which URLs.

## Routing

Uses **React Router v7 in framework mode** — file-based routing with a Vite plugin. This replaces standalone Vite + TanStack Router.

### Setup

Install and configure:
```bash
npm install react-router @react-router/dev
```

`vite.config.ts`:
```typescript
import { reactRouter } from "@react-router/dev/vite";
import tailwindcss from "@tailwindcss/vite";

export default {
  plugins: [
    reactRouter(),
    tailwindcss(),
  ],
};
```

`react-router.config.ts`:
```typescript
import type { Config } from "@react-router/dev/config";

export default {
  ssr: false, // SPA mode — no server rendering
} satisfies Config;
```

### Route File Conventions

| Pattern | Meaning |
|---|---|
| `app/routes/home.tsx` | `/` route |
| `app/routes/login.tsx` | `/login` route |
| `app/routes/_auth/layout.tsx` | Layout/guard for the `_auth` group (no URL segment) |
| `app/routes/_auth/items.tsx` | `/items` (protected) |
| `app/routes/_auth/item.$id.tsx` | `/item/:id` — dynamic param |
| `app/root.tsx` | Root layout wrapping everything |

Routes are declared in `app/routes.ts`:
```typescript
import { type RouteConfig, index, route, layout } from "@react-router/dev/routes";

export default [
  index("routes/home.tsx"),
  route("login", "routes/login.tsx"),
  layout("routes/_auth/layout.tsx", [
    route("items", "routes/_auth/items.tsx"),
    route("item/:id", "routes/_auth/item.$id.tsx"),
  ]),
] satisfies RouteConfig;
```

### Route Module Exports

Each route file can export:

```typescript
// Typed params/search — generated by React Router
import type { Route } from "./+types/items";

// Runs on the client before render — use for auth guard + data prefetch
export async function clientLoader({ params, request }: Route.ClientLoaderArgs) {
  const token = getToken();
  if (!token) throw redirect("/login");
  await queryClient.ensureQueryData(itemsQueryOptions());
  return null;
}

// Default export is the page component
export default function ItemsPage() {
  const { data } = useSuspenseQuery(itemsQueryOptions());
  return <ItemList items={data} />;
}

// Optional: document <title> and <meta>
export function meta(): Route.MetaDescriptors {
  return [{ title: "Items" }];
}
```

### Auth Guard Pattern

The `_auth/layout.tsx` layout file protects all child routes via `clientLoader`:

```typescript
// app/routes/_auth/layout.tsx
import { redirect, Outlet } from "react-router";
import type { Route } from "./+types/layout";
import { getToken } from "~/lib/auth";

export async function clientLoader({ request }: Route.ClientLoaderArgs) {
  if (!getToken()) {
    const redirectTo = new URL(request.url).pathname;
    throw redirect(`/login?redirect=${redirectTo}`);
  }
  return null;
}

export default function AuthLayout() {
  return <Outlet />;
}
```

### Navigation

```typescript
import { useNavigate, Link, NavLink, redirect } from "react-router";

// Programmatic navigation
const navigate = useNavigate();
navigate("/items");

// Redirect from a loader
throw redirect("/login");

// Link components
<Link to="/items">Items</Link>
<NavLink to="/items" className={({ isActive }) => isActive ? "active" : ""}>
  Items
</NavLink>
```

### Reading Route Params & Search

```typescript
import { useParams, useSearchParams } from "react-router";

const { id } = useParams();
const [searchParams] = useSearchParams();
const redirectTo = searchParams.get("redirect");
```

## Data Fetching

Uses **TanStack React Query** for all server state. No global store.

### Layer Separation

```
Route component
  └── hooks/queries/useXxx.ts       ← useSuspenseQuery / useQuery
        └── services/xxx.service.ts ← fetch calls via ApiClient
              └── lib/apiClient.ts  ← singleton HTTP client
```

### Shared QueryClient

Create a single `QueryClient` instance in `lib/queryClient.ts` and export it. Import it in both `root.tsx` (for `QueryClientProvider`) and loaders (for `ensureQueryData`):

```typescript
// lib/queryClient.ts
import { QueryClient } from "@tanstack/react-query";

export const queryClient = new QueryClient({
  defaultOptions: { queries: { staleTime: 1000 * 60 } },
});
```

```typescript
// root.tsx
import { QueryClientProvider } from "@tanstack/react-query";
import { queryClient } from "~/lib/queryClient";

export default function Root() {
  return (
    <QueryClientProvider client={queryClient}>
      <Outlet />
    </QueryClientProvider>
  );
}
```

### API Client

`lib/apiClient.ts` is a singleton `ApiClient` class wrapping native `fetch`. Initialized once with a token getter:

```typescript
initApiClient(getToken);
```

Every request automatically injects the `Authorization: Bearer <token>` header. Supports `GET`, `POST`, `PUT`, `PATCH`, `DELETE`. Handles 204 No Content responses.

### Query Hooks

Define query options as a factory, then consume in hooks and loaders:

```typescript
// hooks/queries/useItems.ts
import { queryOptions, useSuspenseQuery } from "@tanstack/react-query";
import { itemService } from "~/services/item.service";

export const allItemsQueryOptions = () =>
  queryOptions({
    queryKey: ["allItems"],
    queryFn: () => itemService.getAll(),
  });

export const useGetAllItemsQuery = () =>
  useSuspenseQuery(allItemsQueryOptions());
```

Prefetch in a route `clientLoader` so data is ready before render:

```typescript
export async function clientLoader() {
  await queryClient.ensureQueryData(allItemsQueryOptions());
  return null;
}
```

Use `useSuspenseQuery` in the component — when the loader has prefetched, it resolves synchronously.

### Mutation Hooks

One file per mutation in `hooks/mutations/`. Mutations handle cache invalidation and navigation in `onSuccess`:

```typescript
export const useCreateItemMutation = () => {
  const navigate = useNavigate();

  return useMutation({
    mutationFn: (data: CreateItemDto) => itemService.create(data),
    onSuccess: (newItem) => {
      queryClient.invalidateQueries({ queryKey: ["allItems"] });
      navigate(`/item/${newItem.id}`);
    },
  });
};
```

### Optimistic Updates

For immediate UI feedback, use `onMutate` to update the cache optimistically and roll back on error:

```typescript
onMutate: async (updated) => {
  await queryClient.cancelQueries({ queryKey });
  const previous = queryClient.getQueryData(queryKey);
  queryClient.setQueryData(queryKey, /* optimistic state */);
  return { previous };
},
onError: (_err, _vars, context) => {
  queryClient.setQueryData(queryKey, context?.previous);
},
```

## Forms

Uses **React Hook Form** with **Zod** for validation.

### Setup Pattern

```typescript
const schema = z.object({
  name: z.string().min(1, "Name is required"),
});

type FormData = z.infer<typeof schema>;

const { register, handleSubmit, formState: { errors, isSubmitting } } =
  useForm<FormData>({ resolver: zodResolver(schema) });
```

### Nested Dynamic Fields

For forms with dynamic arrays, use `useFieldArray`:

```typescript
const { fields: items, append, remove } = useFieldArray({
  control,
  name: "items",
});

// Nested arrays inside each item:
const { fields: subItems } = useFieldArray({
  control,
  name: `items.${i}.subItems`,
});

// Register nested field:
<input {...register(`items.${i}.subItems.${j}.value`)} />
```

### Error Display

```tsx
{errors.fieldName && (
  <span className="text-error text-sm">{errors.fieldName.message}</span>
)}
```

Use `errors.root` for server-side errors set via `setError("root", ...)`.

## TypeScript

TypeScript strict mode is on. Key patterns:

### Domain Type Files

One `.types.ts` file per domain in `src/types/`. Types are plain interfaces or Zod-inferred:

```typescript
// types/item.types.ts
export interface Item {
  id: string;
  name: string;
  createdAt: string;
}

export type CreateItemDto = Pick<Item, "name">;
```

### Zod Schema Inference

Define the Zod schema once and infer the TypeScript type from it:

```typescript
const schema = z.object({ username: z.string(), password: z.string() });
type LoginCredentials = z.infer<typeof schema>;
```

### Generated Route Types

React Router generates per-route type files in `.react-router/types/`. Import them for typed params and loader data:

```typescript
import type { Route } from "./+types/item";

export async function clientLoader({ params }: Route.ClientLoaderArgs) {
  // params.id is typed
}
```

### Environment Variables

`lib/env.ts` validates env vars at startup with Zod:

```typescript
const envSchema = z.object({
  VITE_API_URL: z.string().url(),
});

export const env = envSchema.parse(import.meta.env);
```

All env vars use the `VITE_` prefix (Vite requirement).

## Styling

**Tailwind CSS + shadcn/ui**. No component-scoped CSS. All styles are utility classes and CSS variables.

### Setup

```bash
npx shadcn@latest init
```

The CLI sets up:
- CSS variables in `app/app.css` (colors, radius, etc.)
- `tailwind.config.ts` extended with shadcn color tokens
- `lib/utils.ts` with the `cn()` helper

Add individual components as needed:
```bash
npx shadcn@latest add button
npx shadcn@latest add input
npx shadcn@latest add dialog
```

Components are copied into `app/components/ui/` — you own the code and can edit them freely.

### The `cn()` Utility

All conditional class merging uses `cn()` from `lib/utils.ts`:

```typescript
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

Use it in every component that has conditional or overridable classes:

```tsx
<button className={cn("rounded px-4 py-2", isActive && "bg-primary", className)} />
```

### Dark Mode

shadcn/ui uses the `class` strategy. Add the `dark` class to `<html>` to enable dark mode:

```tsx
// root.tsx
<html lang="en" className="dark">
```

CSS variables are defined for both `:root` (light) and `.dark` (dark) in `app/app.css`. Forcing dark mode globally means only the `.dark` variables are active.

### CSS Variable Tokens

shadcn/ui defines semantic color tokens as CSS variables. Use them via Tailwind utilities:

| Utility | Purpose |
|---|---|
| `bg-background` | Page background |
| `bg-card` | Card surface |
| `bg-popover` | Popover/dropdown surface |
| `bg-primary` | Primary action color |
| `bg-secondary` | Secondary surface |
| `bg-muted` | Subtle background (inputs, tags) |
| `bg-accent` | Accent/hover highlight |
| `bg-destructive` | Error/danger |
| `text-foreground` | Primary text |
| `text-muted-foreground` | Secondary/muted text |
| `text-primary-foreground` | Text on primary bg |
| `border-border` | Default border |
| `ring-ring` | Focus ring |

## Component Patterns

### Organization

- Components are in `app/components/`, domain-organized
- Route page components live in `app/routes/` and contain minimal logic
- All business logic lives in custom hooks

### Props

Explicit prop interfaces, no spreading `...rest`:

```typescript
interface Props {
  item: Item;
  onSelect: (id: string) => void;
}
```

### Modal Pattern

Controlled modals with `isOpen` + `onClose` props:

```typescript
interface ModalProps {
  isOpen: boolean;
  onClose: () => void;
  onSelect: (item: Item) => void;
}
```

### Loading & Error States

React Query provides `isPending`, `isError`, `error`. Mutation pending state: `mutation.isPending`. Use a Tailwind `animate-spin` spinner or shadcn/ui `Skeleton` for loading states.

```typescript
import type { Config } from "@react-router/dev/config";

  ssr: false,
```

### `tsconfig.json`
```json
{
  "include": ["app", ".react-router/types/**/*"],
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
```

The `~/*` path alias maps to `app/` — use it for all project imports (`~/lib/...`, `~/components/...`).

## Quick-Start Checklist for New Projects

- [ ] Scaffold with `npx create-react-router@latest` (gives React Router framework mode + Vite)
- [ ] Set `ssr: false` in `react-router.config.ts` for SPA mode
- [ ] Install TanStack React Query; create shared `QueryClient` in `lib/queryClient.ts`; wrap root with `QueryClientProvider`
- [ ] Install React Hook Form + Zod + `@hookform/resolvers`
- [ ] Run `npx shadcn@latest init` — sets up Tailwind CSS vars, `lib/utils.ts`, and `components/ui/`
- [ ] Add `dark` class to `<html>` in `root.tsx` to force dark mode
- [ ] Add shadcn/ui components as needed: `npx shadcn@latest add button input card dialog badge table skeleton`
- [ ] Create `lib/apiClient.ts` singleton with token injection
- [ ] Create `lib/env.ts` for Zod-validated env vars
- [ ] Add `~/` path alias in `tsconfig.json` pointing to `app/`
- [ ] Create `app/routes/_auth/layout.tsx` with `clientLoader` auth guard
- [ ] Add `babel-plugin-react-compiler` if needed
- [ ] Enable strict mode in `tsconfig.json`
